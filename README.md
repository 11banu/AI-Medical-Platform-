## Overview

The **AI Medical Platform** is an academic software project that integrates machine learning and deep learning models into a web-based application.

The platform brings together four healthcare-related prediction modules: brain tumor detection, pneumonia detection, heart disease prediction, and diabetes prediction. Users can interact with the implemented modules through a web interface and view the predictions produced by their respective models.

The project demonstrates the integration of Python-based model development, data preprocessing, model evaluation, Flask backend development, and frontend technologies.

> **Project status:** Academic and portfolio project. The models are experimental and have not been established as clinically validated diagnostic systems.

## Objectives

* Explore machine learning applications in healthcare-related classification tasks.

## Features

* Four independent prediction modules.
* Medical image classification for supported brain MRI and chest X-ray inputs.
* Machine learning-based prediction for supported heart disease and diabetes input features.

## Application Modules

### 1. Brain Tumor Detection

Uses a convolutional neural network (CNN) to classify supported brain MRI images into four categories:

* Glioma
* Meningioma
* Pituitary tumor
* No tumor

**Input:** A supported brain MRI image.

**Output:** The predicted class generated by the trained model.

### 2. Pneumonia Detection

Uses a deep learning image-classification model to classify supported chest X-ray images into two categories:

* Normal
* Pneumonia

**Input:** A supported chest X-ray image.

**Output:** The predicted class generated by the trained model.

### 3. Heart Disease Prediction

Uses a trained machine learning classifier to predict the target category from the supported health-related input features.

**Input:** The features required by the implemented prediction form.

**Output:** The model's predicted category.

### 4. Diabetes Prediction

Uses a trained machine learning classification model to estimate the target category from the supported health-related input features.

**Input:** The features required by the implemented prediction form.

**Output:** The model's predicted category.

*The exact fields, preprocessing, and model behavior are defined by each module's implementation.*

## System Architecture

The intended application workflow is:

1. The user opens the web application.
2. The frontend collects the supported image or health-related inputs.
3. Flask receives the request and validates the input.
4. The relevant module preprocesses the input.
5. The trained model generates a prediction.
6. The application returns the result to the user.

## Installation and Setup

### Step 1: Clone the repository

Open a terminal and run:

```bash
git clone https://github.com/11banu/AI-Medical-Platform-.git
cd AI-Medical-Platform-
```

If your repository URL changes, replace the URL above with the current repository's HTTPS clone URL from GitHub.

### Step 2: Create a virtual environment

```bash
python -m venv .venv
```

A virtual environment keeps the project's Python dependencies separate from other applications.

### Step 3: Activate the environment

**Windows — Command Prompt:**

```bat
.venv\Scripts\activate
```

**Windows — PowerShell:**

```powershell
.\.venv\Scripts\Activate.ps1
```

**Linux or macOS:**

```bash
source .venv/bin/activate
```

### Step 4: Upgrade pip

```bash
python -m pip install --upgrade pip
```

### Step 5: Install project dependencies

If the root directory contains a complete `requirements.txt`:

```bash
pip install -r requirements.txt
```

If the modules have separate dependency files, install the dependencies required by the module you intend to run.

Do not assume that every module uses the same packages or versions. Check the imports in its Python files and the corresponding dependency file.

### Step 6: Retrieve large model files

Check that the model files referenced by the application exist in the expected locations.

If large model files are stored using Git Large File Storage (Git LFS), install Git LFS and retrieve the files:

```bash
git lfs install
git lfs pull
```

If a model file is missing, the relevant prediction module may fail to start or generate predictions.

### Step 7: Run the application

If the root `app.py` is the integrated application entry point:

```bash
python app.py
```

Wait for Flask to print its local server address, then open that address in your browser.

The default local address is often `http://127.0.0.1:5000/`, but use the actual address printed by your application.

Stop the development server with `Ctrl + C`.

## Running Individual Modules

Some modules may also have their own Flask application entry points. If so, open a terminal in the relevant module directory and follow its README and dependency instructions.

## Model Evaluation

The modules may use classification metrics such as:

* **Accuracy:** Overall proportion of correct predictions.
* **Precision:** Proportion of positive predictions that are correct.
* **Recall:** Proportion of actual positive cases identified by the model.
* **F1-score:** Harmonic mean of precision and recall.
* **Confusion matrix:** Summary of correct and incorrect classifications by class.
* **ROC-AUC:** Measures discrimination across classification thresholds when applicable.

Evaluation should document the dataset, class distribution, preprocessing, model version, test procedure, and metric definitions. Results from different modules should not be directly compared unless their evaluation settings are comparable.

Use each module's evaluation script, if available, to reproduce its results. Do not describe evaluation results as independently validated unless the validation was actually performed.

## Troubleshooting

### `ModuleNotFoundError`

Activate the virtual environment and install the required dependencies:

```bash
python -m pip install -r requirements.txt
```

Confirm that the terminal is in the correct project directory and that the expected dependency file exists.

### Template not found

Flask commonly looks for HTML templates in a directory named `templates` relative to the application root. Verify the directory name, file location, and template name used by `render_template()`.

### Model file not found

Check that the trained model exists at the path referenced by the prediction code. If using Git LFS, retrieve the actual model files rather than only the small pointer files.

### Prediction errors

Check the input format, image dimensions, class mapping, feature order, preprocessing steps, and model-loading code. Use the error message to identify the failing operation.

### Dependency conflicts

Use the project's supported Python version and install dependencies in a fresh virtual environment. If installation fails, record the Python version and full error message before changing package versions.

## Limitations and Responsible Use

* This project is for educational and research purposes.
* Model outputs are not medical diagnoses.
* Performance depends on training data, preprocessing, class balance, and the evaluation methodology.
* Results may not generalize to different hospitals, devices, populations, or data distributions.
* A high test score alone does not establish clinical usefulness.
* Real-world use would require appropriate independent validation, privacy protection, security testing, clinical oversight, and regulatory review where applicable.

**Do not use this platform to make medical decisions or delay professional medical care.** Consult a qualified healthcare professional for medical concerns.
